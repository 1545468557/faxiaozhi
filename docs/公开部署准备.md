# 法小智公开部署准备

当前前端需要两个 Python 后端：旧业务 API（默认 8010）和新版法律问答 API（默认 8011）。正式前端用 `cd frontend && pnpm build && pnpm start` 启动 Node 生产服务，并通过同源 `/api/bff/**` 转发请求。对外只发布前端 HTTPS 域名；两个 Python 后端留在私有网络。单台轻量服务器的 Docker Compose、Caddy 与操作步骤见 [部署说明](../deploy/README.md)。

## 无登录页的公开模式

两个后端使用相同的环境变量：

```dotenv
AUTH_REQUIRE_LOGIN=1
AUTH_GUEST_MODE=1
AUTH_COOKIE_SECURE=1
GUEST_COOKIE_SECRET=<同一份至少 32 字符的随机值>
GUEST_DAILY_LIMIT=5
GUEST_GLOBAL_DAILY_LIMIT=30
```

访客首次调用 API 时会取得签名的 HttpOnly Cookie；会话、问答记录及导出文件按访客隔离。清除 Cookie 或换设备后，无法找回原访客身份。两个后端必须共享 `GUEST_COOKIE_SECRET` 和持久化的 `data/` 目录；每日总额度只在共享的 `guest_quota.sqlite3` 上生效。对外直连后端仍需由云端防火墙禁止。

前端运行时环境：`BACKEND_BASE_URL`、`V3_BACKEND_BASE_URL` 指向两个私有后端；`ALLOWED_HOSTS` 填真实域名，不填 `*`。模型与北大法宝密钥只进入后端环境，不写进前端变量、镜像或 Git。

## 数据与上线检查

- 云端新建空的账号库、问答库与导出目录；不要把本机已有的私人问答、合同、导出文件和短信日志上传。
- 单独把本机的 `data/statutes.sqlite3` 放进云端持久化数据目录；它不在 Git 仓库中。启动前运行 `uv run python scripts/preflight_public.py`，所有检查为 `true` 后再放开公网流量。
- `runs/`、`exports/`、`data/` 需要持久化存储和备份。单实例运行；当前 SQLite 与进程内会话实现没有多副本协调。
- 先从正式 HTTPS 域名验证首页、法规查找、法律问答、类案研究、合同审查、导出和两位访客之间的数据隔离，再开放域名入口。
- 现有每周法规核验任务作用于本机法规库。部署平台确定后，还需把**已核验的增量**同步到云端法规库并核验线上检索；在同步完成前，不能声称线上法规库每周自动更新。
