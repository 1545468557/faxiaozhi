## 四、卡点 1：域名 + 备案

### 现状

- `chumo.online` **没有任何 A 记录**（NS 在阿里云万网 `dns23/dns24.hichina.com`）
- 服务器上 80/443 从**境外**是通的，Caddy 靠 443 上的 `tls-alpn-01` 成功签到了证书

### 阿里云对未备案域名的实际拦截形态（本次实测）

| 请求 | 结果 |
|---|---|
| `http://106.15.188.206/`（裸 IP） | **308** 正常跳转 |
| `http://<未备案域名>/` | **403**（按 Host 头拦） |
| `https://<未备案域名>/` | **ClientHello 发出后立刻被 RST**（按 SNI 拦） |

⇒ 所以「在服务器上 `curl` 自己是 200，外面的浏览器打不开」是**正常现象**，不是部署错了。
判断是否被备案卡住，必须**从另一台机器**访问。

### 你要做的事

1. 在阿里云 DNS 控制台给 `chumo.online` 加 A 记录 → `106.15.188.206`（`@` 和 `www` 各一条）
2. 办备案（`beian.aliyun.com`）
3. 如果你的**已备案域名**的接入商就是阿里云，那把它指过来可能不用重新备案 —— 值得先试

改完告诉我，我重跑一次 `deploy.sh`（把 `--site-host` 换成新域名），Caddy 会自动换签新证书。

## 五、卡点 2：北大法宝积分为 0

`tools/list` 在所有端点上**都成功**（能看到 60+ 个工具），但真正发起检索就 **HTTP 401**。
报错文案很误导：`Unclassified Authentication Failure`，第一反应会以为是 token 不对。

**实测排除了 token 的可能**：

- 线上与本机的 token **逐字节一致**（长度 43，sha256 前缀 `95c8127cac2928f4`）
- 同一个 token，从本机和从服务器发 `initialize` 都是 **200**（也不是 IP 绑定）
- 手工调一个不花钱的账户工具，**成功**了，它说：
  > **可用积分为 0，调用计费工具会被拒绝；请到门户充值。**
- 再调检索工具，才是那个 401

⇒ **token 有效、协议正确、客户端没问题，就是账户没积分。**
充值入口：https://mcp.pkulaw.com/console/points

在充上之前，产品的「可核验引用」这条核心价值用不了；
好在前端会明确告诉用户「检索失败，这不等于无相关案例」——**这个降级行为是对的，别改**。

## 七、已知的坑（都写在代码注释里了，改之前先读）

1. `uv.lock` 记的是 `files.pythonhosted.org` 的**绝对 URL**，境内 **000 连不通**。
   所以 `Dockerfile.backend` **刻意不加 `--frozen`** —— 加了就会卡在
   `Downloading lxml` 十几分钟不报错，看着像网慢。
2. pnpm 11 的 `strictDepBuilds` **默认 true**，`frontend/.npmrc` 关掉它，
   否则任何人 `pnpm install` 都会以非零码退出。
3. `/api/health` **只有 v3 有**，8010 没有。探活用 8010→`/api/bootstrap`、8011→`/api/health`，
   两个路径**故意不一样**。
4. `/etc/docker/daemon.json` 只能**合并**不能覆盖 —— 这台机器上有别人写的
   `default-address-pools`。
5. 快照传输走「gzip + 4 路并发分片 + md5 校验后原子替换」。单流 scp 只有 25 KB/s，
   158 MB 要传 105 分钟。
