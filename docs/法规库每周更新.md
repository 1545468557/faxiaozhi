# 法规库每周核验更新

每周一 09:00（本机时区）的 Codex 定时任务检查国家法律法规数据库等官方来源，并以北大法宝 MCP 辅助核验。它更新的是法律检索 Agent 使用的 `data/statutes.sqlite3`。原库来自 2026-09-21 的桌面离线文件，包含 2,476 篇；没有可靠的全量增量接口，因此每次运行都要记录实际检查范围，不能把部分核验称为“整库已更新”。

`scripts/check_statute_versions.py` 每次比对 10 部重点法律的法宝沿革，可用 `--title 法规全称` 缩小范围。确认较新版本已经施行后，`--mark-superseded` 会把本地旧版标为“已被修改”并写入 `statute_status_history`，防止它继续作为现行法被默认检索；这一步不等于获取新版全文。新法发现仍需通过官方来源另行检查。

```bash
uv run python scripts/check_statute_versions.py
uv run python scripts/check_statute_versions.py --mark-superseded
```

## 核验及入库要求

1. 查到新增、修订、废止或即将施行的法规时，先确认**完整原文**、标题、公布日期、施行日期、效力状态与来源链接。官方原文优先；北大法宝仅在能给出对应版本完整原文时作为入库来源。摘要、搜索片段和模型生成文本只能作为线索。
2. 对照本地同名法规。若有多个同名版本，必须指定准确的 `bbbs`；不能按标题猜测。核对条文总数，生成一篇法规对应一个 JSON 候选。候选文件放在 `data/statute_updates/`，该目录不提交到 Git。
3. 先预检，再入库，再核对检索结果与 `statute_update_history`。脚本在单个 SQLite 事务内替换对应篇目的元数据、条文和 FTS 索引，并保留此前版本。未通过核验的候选不入库。

候选 JSON 字段：`title`、`category`、`organ`、`publish_date`、`effective_date`、`status_code`、`status_text`、`source_url`、`source_text`（完整原文）、`source_sha256`（对去除首尾空白后的原文计算 SHA-256）、`expected_article_count`（不含题注）、`verified_at`（带时区的 ISO 时间）；同名多版本时还需 `bbbs`。效力代码可用 `valid`、`pending`、`amended`、`repealed`、`invalid`、`na`。

```bash
uv run python scripts/apply_statute_update.py data/statute_updates/一篇法规.json
uv run python scripts/apply_statute_update.py data/statute_updates/一篇法规.json --apply
```

预检为默认行为，不写库。第一次实际更新前，`meta.imported_at` 仍表示原始快照日期；增量更新时间另记在 `meta.last_incremental_update_at`。如果本机、官方站点或 MCP 不可用，定时任务应报告失败并保留原库，不得猜测更新。
