# 短信验证码通道：开通清单

> 面向「现在就想让验证码真的发出去」的执行清单。
> 代码侧已经完成（两条通道都已实现并测试通过），**缺的只有账号侧的配置**。

## 0. 先说清楚：为什么是两段式

短信通道有两条，代码都写好了，靠 `.env` 里一行 `SMS_PROVIDER` 切换，业务代码不动：

| `SMS_PROVIDER` | 谁生成验证码 | 短信里的发件人 | 需要什么 |
| --- | --- | --- | --- |
| `pnvs`（**现在走**） | 阿里云 | **阿里云赠送的签名**（不是「法小智」） | 个人实名认证即可，**免资质、免签名、免模板** |
| `aliyun`（**将来走**） | 我们 | **自己的签名**（可以带「法小智」） | 企业主体 + 资质 + 签名报备 |

为什么会这样：签名的合法来源现在只剩「企事业单位全称或简称」和「已注册商标名」。
「法小智」作为**产品名**不是合法来源 —— 除非有注册商标，或者它本来就在主体名称里。
所以顺序是：**先用赠送签名把验证码跑通（不阻塞任何人），等主体办下来再切成自己的署名。**

## 1. 阶段一：开通号码认证服务（今天就能做完）

按顺序做，第 3 步是本清单的核心产出。

1. **阿里云账号完成个人实名认证。**
2. **开通「短信认证」功能**：号码认证服务控制台 → <https://dypns.console.aliyun.com/functions>
3. **记下两个值**（这是唯一必须手动抄下来的东西）：
   - 「**赠送签名配置**」页 → 选一个签名 → 记下**签名名称**，形如 `速通互联验证码`
   - 「**赠送模板配置**」页 → 选一个模板 → 记下**模板编号**，形如 `100001`

   ⚠️ 赠送签名与赠送模板**必须配套使用**，不能交叉（赠送签名 + 自定义模板是不允许的）。
4. **买「短信认证」套餐包**，在号码认证服务控制台买。
   ⚠️ 它和「短信服务」是**两个独立产品**：不同端点（`dypnsapi` / `dysmsapi`）、不同控制台、
   不同套餐包。**短信服务的免费测试包不能抵扣这里的费用。**
5. **建 RAM 用户**取 AccessKey，授予 `AliyunDypnsFullAccess`。
   （不要用主账号 AccessKey。）
6. **写进 `.env`**：

```bash
SMS_PROVIDER=pnvs
SMS_ALIYUN_ACCESS_KEY_ID=<第 5 步的 ID>
SMS_ALIYUN_ACCESS_KEY_SECRET=<第 5 步的 Secret>
SMS_PNVS_SIGN_NAME=<第 3 步的签名名称>
SMS_PNVS_TEMPLATE_CODE=<第 3 步的模板编号>
```

7. **先干跑，确认参数对了再真发**：

```bash
SMS_DRY_RUN=1 .venv/bin/python -c "from app.auth import sms; sms.send_code('13800000000', None, 'login')"
```

日志会打印签名名、模板号、码长、有效期、频控间隔 —— **不含验证码**（这个通道下我们本来也拿不到）。
核对无误后把 `SMS_DRY_RUN` 去掉，真发一条验证。

### 只支持中国大陆手机号

号码认证服务目前只支持国家码 `86`。我们本来就只收 11 位大陆号，无影响。

### 计费口径

只收短信发送费，**按运营商回执状态计费**（提交成功但运营商回执失败不计费）；**核验免费**。

## 2. 阶段二：切成自己的署名（等主体下来）

前提：你已经有一个**企业主体**（含个体工商户），并且「法小智」能从主体名称里取出来。

1. 阿里云账号**升级企业认证**（个人认证账号无法新增申请自用资质）。
   升不了的话就走「他用资质」，需要对方营业执照 + 法人信息 + 盖章的授权委托书。
2. 短信服务控制台 → 资质管理 → 新增资质（自用 / 他用）。
3. 申请**签名**，来源选「企事业单位名」，名称从企业全称里**连续**取字。
   官方口径很死：
   - 全称「杭州阿里云网络技术有限公司」→ ✅【杭州阿里云网络技术】
   - ❌【阿里】多个地区都有，不唯一；❌【阿里科技】没完全包含在全称里；❌【杭里网络】跳字
   → 所以要拿到的多半是**【XX法小智科技】**这类带地域或行业的写法，未必是光秃秃三个字。
4. 申请**模板**。**内容只写验证码，一个字都不要写产品是干什么的。**
   ⚠️ 阿里云模板禁用内容里**明确列着「法律维权」**，而且签名 FAQ 写明
   「法律调解、催收、金融等相关业务的签名**一旦被禁用，不支持复开，也不允许换签名继续发送同类业务**」。
   这是最高级别管控，没有申诉空间。同理，签名名里别出现「法律」「维权」「咨询」。
5. **等运营商实名报备**：平均 5–7 个工作日，部分运营商 7–10 个，官方**不承诺时效**。
   控制台签名管理页看「运营商报备结果」列。
   「报备成功」= 至少一个子端口号通过了，**不等于可以立刻批量发**。先少量多次试。
6. 改 `.env`（AccessKey 复用，不用换）：

```bash
SMS_PROVIDER=aliyun
SMS_SIGN_NAME=<第 3 步的签名名>
SMS_TEMPLATE_CODE=<第 4 步的模板 CODE>
```

7. **向移动 / 联通 / 电信各发一条验证**。三种运营商是分别报备的，
   可能「部分成功、部分失败」，这是正常现象，不是配置错了。

## 3. 排错表

| 错误码 | 含义 | 怎么办 |
| --- | --- | --- |
| `FUNCTION_NOT_OPENED` | 号码认证服务的「短信认证」没开通 | 去控制台开通（阶段一第 2 步） |
| `FREQUENCY_FAIL` | 服务商频控 | 同一号码发太频繁，等一会儿 |
| `BUSINESS_LIMIT_CONTROL` | 号码天级流控 | 这个号今天发太多了 |
| `INVALID_PARAMETERS` | 参数不合法 | 多半是签名与模板**不配套**，或模板占位符名不是 `code` |
| `MOBILE_NUMBER_ILLEGAL` | 号不被接受 | 只支持大陆 11 位手机号 |
| `InvalidAccessKeyId.NotFound` | AccessKey 不对 | 核对 `SMS_ALIYUN_ACCESS_KEY_ID` |
| `SignatureDoesNotMatch` | 签名校验失败 | Secret 不对，或服务器**系统时间偏差过大** |
| `PORT_NOT_REGISTERED` | 端口未完成运营商实名报备 | **只有阶段二会遇到**，等报备或查控制台 |
| `isv.SMS_SIGNATURE_ILLEGAL` | 签名未报备 / 与模板不匹配 | 阶段二，核对签名名 |
| `isv.SMS_TEMPLATE_ILLEGAL` | 模板未报备或已删 | 阶段二，核对模板 CODE |
| `isv.AMOUNT_NOT_ENOUGH` | 套餐余额不足 | 充值（注意要充**号码认证服务**的包） |

## 4. 上线前必须过的闸门

`Scripts/preflight_public.py` 已加入两条短信检查：

- `sms_channel_is_real`：`SMS_PROVIDER` 不能是 `mock`、也不能没设
- `sms_channel_configured`：按通道检查对应密钥是否齐全

**为什么必须有这两条**：`SMS_PROVIDER=mock` 在公网上**不报错、看起来一切正常**，
它只是把**明文验证码**写进服务端日志和 `data/sms-outbox.jsonl` ——
拿到日志的人就能登录成任意手机号。而本地开发长期停在 mock，上线时最容易忘的正好是这一行。

跑法：

```bash
.venv/bin/python Scripts/preflight_public.py
```

全部 `true` 才放开公网流量。

## 5. 本地开发照旧

本地继续 `SMS_PROVIDER=mock`（默认值），不用改任何东西。

因为 `pnvs` 通道下**我们拿不到验证码**（阿里云生成并保管），本地如果切成 pnvs，
就没法登录、没法跑 e2e、也没法演示。所以：

- **本地 / 演示** → `mock`（验证码写进 `data/sms-outbox.jsonl`，方便调试）
- **线上** → `pnvs`（或将来 `aliyun`）

这不是妥协，是必须。三条通道都是插拔式的，切换只改 `.env` 一行。
